# 商品价格预测分析系统 · 数据库设计说明

| 项目    | 内容                      |
| ----- | ----------------------- |
| 系统名称  | 商品价格预测分析系统              |
| 数据库名  | `price_forecast`        |
| 数据库引擎 | MySQL 8.4 LTS（InnoDB）   |
| 字符集   | `utf8mb4`（全库统一，保证中文不乱码） |
| 排序规则  | `utf8mb4_general_ci`    |
| 文档版本  | v1.0                    |
| 编写日期  | 2026-10-20              |

---

## 一、概述

### 1.1 设计目标

本系统围绕「商品价格」这一核心业务，完成从**数据爬取 → 清洗入库 → 查询分析 → 价格预测 → 波动告警 → 对话问答**的完整链路。数据库是整条链路的唯一数据源（任务书硬性约束：LLM 不能编造数据，所有业务数据必须由后端工具读写数据库获得）。

### 1.2 设计原则

1. **主键统一**：每张表都设 `id BIGINT AUTO_INCREMENT` 作为物理主键，业务编号（如 `goods_code`）单独设唯一索引。
2. **金额用 DECIMAL**：价格、涨跌幅、阈值、置信度等数值一律用 `DECIMAL`，**禁用 `FLOAT` / `DOUBLE`**（浮点数存金额有精度误差）。
3. **字符集统一 `utf8mb4`**：商品名（小麦、猪肉、蔬菜）等中文必须 `utf8mb4`，否则乱码。
4. **通用字段**：每张业务表都带 `create_time`（创建时间），需要追踪处理流程的再带 `update_time` / `handle_time`。
5. **去重与防抖靠唯一约束**：不依赖应用层判断，直接在数据库层用 `UNIQUE KEY` 保证数据幂等。

### 1.3 关于任务书两处不一致的统一

| 问题     | 任务书原文                                                 | 本文档统一方案                         |
| ------ | ----------------------------------------------------- | ------------------------------- |
| 表名冲突   | 实体定义叫 `forecast`，功能需求第 4 条又写"写入 `price_prediction` 表" | 统一为 **`forecast`**（在项目文档中注明已统一） |
| 数据库不一致 | 技术栈写 MySQL，第 1 周却写"SQLite 数据库表结构设计"                   | 统一为 **MySQL 8.4**               |

## 三、表结构详细设计

> 说明：字段类型列中的 `DECIMAL(m,n)` 表示"总共 m 位数字，其中 n 位小数"。
> 例如 `DECIMAL(14,4)` 可存 `9999999999.9999`，足够覆盖元/公斤、元/吨两种单位的价格。

### 表 1：商品分类表 `goods_category`

存放商品大类（粮食、肉类、蔬菜等），供商品表引用。

| 字段名             | 类型           | 约束                       | 默认值               | 说明                  |
| --------------- | ------------ | ------------------------ | ----------------- | ------------------- |
| `id`            | BIGINT       | NOT NULL, AUTO_INCREMENT | -                 | 主键                  |
| `category_code` | VARCHAR(32)  | NOT NULL, UNIQUE         | -                 | 分类编码（业务唯一）          |
| `category_name` | VARCHAR(50)  | NOT NULL                 | -                 | 分类名称，如：粮食 / 肉类 / 蔬菜 |
| `description`   | VARCHAR(200) | NULL                     | NULL              | 分类描述                |
| `create_time`   | DATETIME     | NOT NULL                 | CURRENT_TIMESTAMP | 创建时间                |

- **主键**：`PRIMARY KEY (id)`
- **唯一约束**：`UNIQUE KEY uk_category_code (category_code)`CR

> 设计说明：任务书实体里写了"关联商品列表"字段，这里**不单独存**——某分类下有哪些商品，通过商品表里的 `category_id` 反查即可，存了反而要维护两份、易不一致。

---

### 表 2：商品表 `goods`

存放具体商品（小麦、猪肉、包菜等）。

| 字段名                | 类型          | 约束                       | 默认值               | 说明                          |
| ------------------ | ----------- | ------------------------ | ----------------- | --------------------------- |
| `id`               | BIGINT      | NOT NULL, AUTO_INCREMENT | -                 | 主键                          |
| `goods_code`       | VARCHAR(32) | NOT NULL, UNIQUE         | -                 | 商品编号（业务唯一）                  |
| `goods_name`       | VARCHAR(50) | NOT NULL                 | -                 | 商品名称，如：小麦 / 猪肉 / 包菜         |
| `category_id`      | BIGINT      | NOT NULL                 | -                 | 所属分类，关联 `goods_category.id` |
| `source_platform`  | VARCHAR(50) | NULL                     | NULL              | 数据来源平台                      |
| `update_frequency` | VARCHAR(20) | NULL                     | NULL              | 数据更新频率，如：每日 / 每小时           |
| `create_time`      | DATETIME    | NOT NULL                 | CURRENT_TIMESTAMP | 创建时间                        |

- **主键**：`PRIMARY KEY (id)`
- **唯一约束**：`UNIQUE KEY uk_goods_code (goods_code)`
- **索引**：`KEY idx_category (category_id)`（按分类查商品时加速）

> 设计说明：任务书实体写"商品类别（小麦/猪肉/蔬菜等）"，这里澄清层级——**分类是"粮食/肉类/蔬菜"，商品是"小麦/猪肉/包菜"**。用 `category_id` 关联分类表，比在商品表里塞一个类别字符串更规范。

---

### 表 3：价格数据表 `price_data`

存放爬取/清洗后的历史价格（全系统数据基础）。

| 字段名           | 类型            | 约束                       | 默认值               | 说明            |
| ------------- | ------------- | ------------------------ | ----------------- | ------------- |
| `id`          | BIGINT        | NOT NULL, AUTO_INCREMENT | -                 | 主键            |
| `goods_id`    | BIGINT        | NOT NULL                 | -                 | 关联 `goods.id` |
| `price`       | DECIMAL(14,4) | NOT NULL                 | -                 | 价格            |
| `price_unit`  | VARCHAR(20)   | NOT NULL                 | -                 | 价格单位：元/公斤、元/吨 |
| `price_date`  | DATE          | NOT NULL                 | -                 | 价格对应日期        |
| `change_rate` | DECIMAL(8,4)  | NULL                     | NULL              | 涨跌幅（%）        |
| `source_url`  | VARCHAR(255)  | NULL                     | NULL              | 数据来源 URL      |
| `crawl_time`  | DATETIME      | NOT NULL                 | CURRENT_TIMESTAMP | 抓取时间          |

- **主键**：`PRIMARY KEY (id)`
- **唯一约束（去重关键）**：`UNIQUE KEY uk_goods_date (goods_id, price_date)`
- **索引**：`KEY idx_goods (goods_id)`、`KEY idx_price_date (price_date)`（时间区间查询加速）

> 设计说明：
>
> 1. **去重靠 `UNIQUE(goods_id, price_date)`**：同一商品同一天只能存一条。爬虫反复抓取时用 `INSERT ... ON DUPLICATE KEY UPDATE` 即可天然去重（幂等）。
> 2. 单位单列 `price_unit`：任务书写"价格(元/公斤或元/吨)"，说明同一张表里单位可能不同，必须用独立字段标注，不能写死在价格里。

---

### 表 4：预测结果表 `forecast`

存放离线预测 / 实时预测的输出结果。

| 字段名              | 类型            | 约束                       | 默认值               | 说明                               |
| ---------------- | ------------- | ------------------------ | ----------------- | -------------------------------- |
| `id`             | BIGINT        | NOT NULL, AUTO_INCREMENT | -                 | 主键                               |
| `goods_id`       | BIGINT        | NOT NULL                 | -                 | 关联 `goods.id`                    |
| `forecast_date`  | DATE          | NOT NULL                 | -                 | 预测的日期                            |
| `forecast_price` | DECIMAL(14,4) | NOT NULL                 | -                 | 预测价格                             |
| `model_name`     | VARCHAR(50)   | NOT NULL                 | -                 | 预测模型名称：ARIMA / Prophet / XGBoost |
| `confidence`     | DECIMAL(5,4)  | NULL                     | NULL              | 置信度（0 ~ 1）                       |
| `basis_summary`  | TEXT          | NULL                     | NULL              | 预测依据摘要                           |
| `create_time`    | DATETIME      | NOT NULL                 | CURRENT_TIMESTAMP | 创建时间                             |

- **主键**：`PRIMARY KEY (id)`
- **唯一约束**：`UNIQUE KEY uk_goods_model_date (goods_id, model_name, forecast_date)`（同一模型同一商品同一日期只保留一条预测）
- **索引**：`KEY idx_goods_date (goods_id, forecast_date)`

> 设计说明：任务书要求输出"预测价格、置信区间、模型名称、准确率指标"。置信区间可拆成两个字段，本设计先用 `confidence` 承载置信度；如需完整置信区间，可在后续迭代增加 `lower_bound` / `upper_bound` 两个 `DECIMAL(14,4)` 字段。

---

### 表 5：用户查询记录表 `query_log`

存放 Agent 对话中的每一次用户查询，用于分析与多轮对话记忆。

| 字段名                | 类型          | 约束                       | 默认值               | 说明                       |
| ------------------ | ----------- | ------------------------ | ----------------- | ------------------------ |
| `id`               | BIGINT      | NOT NULL, AUTO_INCREMENT | -                 | 主键                       |
| `user_id`          | VARCHAR(64) | NULL                     | NULL              | 用户标识                     |
| `session_id`       | VARCHAR(64) | NULL                     | NULL              | 会话标识（多轮对话归组）             |
| `query_content`    | TEXT        | NOT NULL                 | -                 | 查询内容                     |
| `intent_type`      | VARCHAR(30) | NULL                     | NULL              | 查询意图分类：趋势 / 原因 / 对比 / 预测 |
| `response_time_ms` | INT         | NULL                     | NULL              | 响应时间（毫秒）                 |
| `create_time`      | DATETIME    | NOT NULL                 | CURRENT_TIMESTAMP | 创建时间                     |

- **主键**：`PRIMARY KEY (id)`
- **索引**：`KEY idx_session (session_id)`、`KEY idx_user (user_id)`

> 设计说明：`session_id` 是任务书实体没写、但**硬性约束要求**的字段——任务书要求"同一会话中 Agent 需保持上下文记忆，支持多轮对话"。没有 `session_id`，多轮对话就无法归组。

---

### 表 6：价格告警记录表 `price_alert`

存放触发的价格波动告警及处理状态。

| 字段名              | 类型           | 约束                       | 默认值               | 说明                    |
| ---------------- | ------------ | ------------------------ | ----------------- | --------------------- |
| `id`             | BIGINT       | NOT NULL, AUTO_INCREMENT | -                 | 主键                    |
| `goods_id`       | BIGINT       | NOT NULL                 | -                 | 关联 `goods.id`         |
| `alert_type`     | VARCHAR(10)  | NOT NULL                 | -                 | 告警类型：上涨 / 下跌          |
| `change_rate`    | DECIMAL(8,4) | NOT NULL                 | -                 | 触发时的变化率（%）            |
| `threshold`      | DECIMAL(8,4) | NOT NULL                 | -                 | 触发时的阈值（%），快照          |
| `alert_status`   | VARCHAR(10)  | NOT NULL                 | '未处理'             | 告警状态：未处理 / 已处理 / 已忽略  |
| `notify_channel` | VARCHAR(30)  | NULL                     | NULL              | 通知渠道：站内消息 / 邮件 / 企业微信 |
| `notify_status`  | VARCHAR(10)  | NULL                     | NULL              | 通知状态                  |
| `create_time`    | DATETIME     | NOT NULL                 | CURRENT_TIMESTAMP | 告警时间                  |
| `handle_time`    | DATETIME     | NULL                     | NULL              | 处理时间                  |

- **主键**：`PRIMARY KEY (id)`
- **唯一约束（防抖关键）**：`UNIQUE KEY uk_goods_type_date (goods_id, alert_type, DATE(create_time))`
- **索引**：`KEY idx_status (alert_status)`、`KEY idx_goods (goods_id)`

> 设计说明：
>
> 1. **防抖靠 `UNIQUE(goods_id, alert_type, 当天)`**：同一商品同一方向一天只告警一次，天然避免"告警风暴"。
> 2. `threshold` 存的是**触发时那一刻的快照**，因为阈值之后可能被管理员修改，告警记录应保留当时的判断依据。

---

### 表 7（新增）：预警阈值配置表 `alert_threshold`

任务书功能需求要求"管理员可在后台配置每种商品的预警阈值（默认 10%，支持上涨/下跌两个方向）"。原 6 张表里没有地方存这个配置，故**新增一张配置表**。

| 字段名              | 类型           | 约束                       | 默认值               | 说明                      |
| ---------------- | ------------ | ------------------------ | ----------------- | ----------------------- |
| `id`             | BIGINT       | NOT NULL, AUTO_INCREMENT | -                 | 主键                      |
| `goods_id`       | BIGINT       | NOT NULL, UNIQUE         | -                 | 关联 `goods.id`（一个商品一条配置） |
| `up_threshold`   | DECIMAL(8,4) | NOT NULL                 | 10.0000           | 上涨预警阈值（%）               |
| `down_threshold` | DECIMAL(8,4) | NOT NULL                 | 10.0000           | 下跌预警阈值（%）               |
| `create_time`    | DATETIME     | NOT NULL                 | CURRENT_TIMESTAMP | 创建时间                    |
| `update_time`    | DATETIME     | NULL                     | NULL              | 更新时间                    |

- **主键**：`PRIMARY KEY (id)`
- **唯一约束**：`UNIQUE KEY uk_goods (goods_id)`

> 设计说明：阈值从 `price_alert` 里拆出来独立成表，是因为"配置"和"告警事件"是两码事——配置长期有效、可反复修改；告警记录是历史快照、只增不改。定时任务计算变化率后，读本表判断是否超阈值。

## 四、表关系设计（ER 关系）

```
goods_category (1) ────< (N) goods (1) ────< (N) price_data
                                        └───< (N) forecast
                                        └───< (N) price_alert
                                        └─── (1) alert_threshold

query_log 独立，通过 session_id 归组对话，不与商品强关联
```

- `goods_category` ↔ `goods`：**一对多**（一个分类下有多个商品）
- `goods` ↔ `price_data`：**一对多**（一个商品有多条历史价格）
- `goods` ↔ `forecast`：**一对多**（一个商品有多条预测）
- `goods` ↔ `price_alert`：**一对多**（一个商品有多条告警）
- `goods` ↔ `alert_threshold`：**一对一**（一个商品一套阈值配置）

> 外键说明：学习阶段建议**先不加数据库外键约束（FOREIGN KEY）**，用 `goods_id` 等字段做"逻辑关联"即可。原因：加外键会让批量导入、清数据、爬虫写入变得麻烦，逻辑关联已能满足需求；等你对数据一致性有更高要求时再加。

## 五、关键设计决策说明（评分要点）

| #   | 决策                                                 | 理由                                             |
| --- | -------------------------------------------------- | ---------------------------------------------- |
| 1   | 价格用 `DECIMAL(14,4)`                                | 浮点数存金额有精度误差，是隐含扣分点                             |
| 2   | `price_data` 加 `UNIQUE(goods_id, price_date)`      | 满足任务书"去重"要求，并发爬取靠它做幂等                          |
| 3   | `price_alert` 加 `UNIQUE(goods_id, alert_type, 当天)` | 满足任务书"防抖机制"，一天一方向只报一次                          |
| 4   | 统一 `forecast` 表名                                   | 解决实体 `forecast` 与功能需求 `price_prediction` 的命名冲突 |
| 5   | 补 `query_log.session_id`                           | 满足"多轮对话记忆"硬性约束                                 |
| 6   | 新增 `alert_threshold` 表                             | 满足"按商品配置阈值"功能需求                                |
| 7   | 全库 `utf8mb4`                                       | 保证中文商品名不乱码                                     |
| 8   | 业务编号（`goods_code` 等）加唯一索引                          | 满足任务书"编号(唯一)"要求，同时物理主键用自增 `id`                 |

## 六、建表顺序

由于存在逻辑关联，**建议按以下顺序建表**（没加外键约束时顺序不强制，但养成好习惯）：

```
1. goods_category    →  2. goods    →  3. price_data / forecast / price_alert / alert_threshold
                                                  →  4. query_log（独立，可放最后）
```
